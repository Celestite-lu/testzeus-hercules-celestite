# 面试简历材料 — 「录制即用例」（通俗版）

> 这份文件是什么：面试前要背的核心材料，分五部分——三个岗位的简历写法、30 秒/15 秒的口头介绍、几个关键数字的"口径卡"、数字出处速查表、以及绝不能说错的话（红线）。数据截至第四轮实验（2026-09-24 冻结）。
> 两条使用原则：① 每个数字都能在 dev_docs 里指出处（§4 表），被追问时 3 秒定位；② 所有边界主动说，不等面试官挖出来。诚实是第一原则。

## 0. 先弄懂这十个词（全文的行话都在这）

1. **口径**：一个数字是在什么条件下算出来的——用了哪些任务、给多长时间、怎么判分、跑几次。**口径不同的两个数字不能直接比大小**，这是全文最重要的概念。
2. **零样本 / 文本-DOM**：零样本 = 事先不给模型任何解题示例；文本-DOM = 模型只能读页面的文字和结构信息（DOM），不能看截图。两者合起来描述我们的实验设定。
3. **公开可比带 47-60%**：文献里和我们同口径（零样本、只读 DOM、全 125 个任务）的 GPT-4 级 agent，公开成绩落在 47% 到 60% 之间。这是我们唯一引用的参照区间。
4. **单 seed 单次**：每个任务只跑一次（随机种子固定一个）。好处是省钱，代价是结果有随机波动——我们测过波动幅度（约 ±10 格，即 ±8%），并主动披露。
5. **判分 / 页面原生奖励**：MiniWoB++ 每个任务页面自带判定，做没做对页面自己知道。我们只认页面判的分，**不用另一个大模型当裁判**（裁判自己会出错）。
6. **无效格 / clean 口径**：125 个任务格子里，有安全违规嫌疑的会被剔除（记为无效格），剔完剩下的主成绩就是 clean（干净）口径。
7. **变异实验（exp001）**：对同一个演示应用故意做 5 种页面改动（比如把所有 id 换掉、把按钮文字改写），看两种测试方法谁还能活下来。6 条流程 × 5 种改动 × 2 种方法 = 60 格。
8. **selector 基线**：传统 Playwright 脚本，靠 id / class / data-testid 定位元素。前端一改版这些定位符就失效，业内叫"selector 腐烂"——本项目的靶子就是这个痛点。
9. **主指标 1.00 vs 0.667**：三种结构性改动（字段调换、布局、标识符随机化）下存活率的平均值，本工具满分 1.00，selector 基线 0.667——差距全部来自标识符随机化那一项。
10. **md 表**：执行引擎把页面元素提炼成的一张带语义标签（aria-label、label、placeholder、可见文字）的清单。agent 靠语义找元素、不依赖 id/class——"UI 改版不挂"靠的就是它。

## 1. 三个岗位变体（简历项目段怎么写）

> 同一个项目的三种写法，按投递岗位选一个。标题行是面试官扫简历 10 秒内看到的全部，所以必须带"基于开源内核二开"的限定——不写会被当成全自研，后面贡献边界一问就翻车。

### 1.1 AI Agent 开发方向（突出：多 agent 编排 + 四轮迭代方法论 + 评测素养）

> **录制即用例：AI Web 测试工具链 + MiniWoB++ 全量基准四轮迭代（43.2%→61.6%）**（独立开发，基于开源执行内核 Hercules 二次开发）

- 设计零样本、只读页面文本的实验口径，跑通 MiniWoB++ 全量 125 个任务类，四轮迭代 43.2%→46.4%→47.2%→61.6%，越出同口径公开成绩带（47-60%）的上沿
- 建立逐格归因的迭代方法：每轮对 125 格逐一分析失败原因，据此发现"页面上看得见、但语义表里点不到"的元素盲区；扩展语义元素表后单轮多通过 17 格（24 个新通过格里 17 格有日志实证），超时格 21→9，无效格连续两轮为零
- 构建防作弊的评测纪律：只认页面自带判分（无 LLM 裁判）、五类作弊扫描、每轮实验前后各一次安全审查全部通过；一次绕过扫描的事件按事先登记的规则把 10 格判无效——宁可分数难看，不洗白
- 实现录制→蒸馏→语义执行→失败归因的四命令管线（录制器、蒸馏器、归因器、编排 CLI 为自研，共 492 条 pytest），归因器 13 条错误签名规则优先定类，模型只做摘要且必须引用证据，查无证据强制降级为"无法定位"
- 实际克隆同源架构前身 Agent-E 的仓库逐项对照（13 项机制全部继承或覆盖）；核实常被引用的 81.6% 并不属于 Agent-E（实为另一篇论文 HxAgent 的数字），主动废弃这个错误锚点并固化更正
- 构建可复现的实验基建：随机种子派生固定、引擎改动全部做成开关且默认关闭、关闭状态用 golden 文件逐字节锁定（保证"没开开关时和上游行为完全一致"），单轮全量实验 12.2M token 内完成

### 1.2 测试开发方向（突出：确定性蒸馏 + 防作弊评测纪律 + 归因闭环）

> **录制转自然语言用例的 AI E2E 测试工具：确定性规则蒸馏 + 语义化执行 + 失败自动归因**（独立开发，基于开源执行内核二开，492 条测试）

- 实现确定性三层蒸馏管线：规则模板生成骨架（不用 LLM）→ 可选 LLM 润色 → 事实回查校验（生成的每个字面值必须能在录制数据里找到原文，找不到就整体回退纯模板）——骨架的正确性对模型能力零依赖
- 设计受控 UI 变异实验（6 流程 × 5 变异 × 2 方法 = 60 格）：标识符随机化下生成用例存活 6/6、selector 式基线 0/6，主指标 1.00 vs 0.667；文案改写 5/6 如实报告为概率性边界
- 实现失败归因器：13 条错误签名规则优先定类（LLM 不参与），模糊区才交 LLM 做摘要、且必须引用证据（日志行/截图/工具输出原文），程序回查引用真实性，查无此证强制降级"无法定位"——在真实失败样本上完成闭环验证
- 建立评测防作弊纪律：页面原生判分唯一权威、五类作弊扫描、每轮实验前后双安全审查；绕过扫描事件按预登记契约压分 10 格（宁可掉分不洗分）
- 编写 492 条 pytest（recorder 21 / distiller 68 / evaluation 77 / attributor 81 / cli 54 / benchmark 191，2026-09-24 --collect-only 实测），并能定位自身 fixture 隔离缺陷（session 级 playwright 实例冲突、特定子集乱序误红 6 条）
- 量化执行成本：30 次真实 LLM 执行共 411 万 token（均值 13.7 万/次，单场景 7.3 万-42 万）；MiniWoB++ 全量 125 任务单轮 12.2M token 内完成

### 1.3 前端 + AI 方向（突出：前端测试痛点的诚实解法——能讲清哪 6/6、哪 5/6）

> **为前端团队打造「录制即用例」AI E2E 测试工具：点一遍页面即得用例、UI 改版不挂、失败自动定责**（独立开发，基于开源执行内核二开）

- 实现注入式 JS 事件录制器（bookmarklet 免安装）：手动操作页面即捕获点击/输入事件流，确定性蒸馏成 Gherkin 用例，生成用例首轮真实执行通过率 6/6
- 受控变异实验（6 流程 × 5 变异 × 2 方法）实证 selector 腐烂痛点：id/class/testid 全部随机化（模拟前端改版）下，语义执行用例存活 6/6，selector 式 Playwright 脚本 0/6
- 语义执行每次现场理解 DOM（属性蒸馏接近无障碍树），不保存任何 selector；失败归因五档定类（产品 bug/用例过时/环境/agent 能力上限/无法定位，13 条签名规则优先）
- 基于开源 LangGraph 多 agent 执行内核二次开发，跑通 MiniWoB++ 全量 125 任务类、四轮迭代 43.2%→61.6%，验证语义执行在 125 类页面交互上的规模化能力
- 内建安全默认值：密码录制即掩码、LLM key 只经子进程环境变量注入、日志强制脱敏（双 key 全库扫描零命中）
- 如实声明边界：多页导航 v1 不支持（检测到跨页跳转就干净退出、不落脏数据）；跨域 iframe/closed shadow DOM/canvas 是硬盲区；文案改写自愈 5/6 是概率性的

## 3. 口径卡（背熟：被追问任何数字时一口气讲完）

### 卡 1：61.6% 的六个要素

一口气版：**MiniWoB++ browsergym registry 全量 125 任务类；零样本、只读页面文本（md 属性蒸馏，约等于无障碍树的信息量，非视觉）；模型 GLM 5.3 系列（planner 用 glm-5.3 / 导航用 glm-5.3-flash；第二轮起切换，第一轮是 deepseek-v4-pro）；每个任务限时 240 秒（原版论文是 10 秒，这个放宽在每份报告里都主动写明）；每任务单 seed 单次；判分只用页面原生 `WOB_RAW_REWARD_GLOBAL > 0`（无 LLM 裁判），官方口径=干净口径、零无效格。**

结论措辞：**"越出同口径（零样本、只读 DOM、全任务集）公开可比带 47-60% 的上沿"**——不说 SOTA，不跨口径比数字。被问"为什么放宽到 240 秒"：MiniWoB 原版 10 秒是给强化学习设定的；LLM agent 每一步要推理加工具调用，远超那个节奏，公开的同档工作也没用 10 秒。计时差异是披露项不是隐藏项；可比性的依据是观察方式和零样本设定。

### 卡 2：1.00 vs 0.667 的完整限定

一口气版：**受控实验，6 条录制流程 × 5 种 UI 变异 × 2 种方法 = 60 格；单 demo 应用、单模型（deepseek-v4-pro）。主指标 = 三种结构性变异（字段调换/布局/标识符随机化）存活率均值：本工具 1.00、selector 基线 0.667。**核心结论是 M3（id/class/testid 全随机化）6/6 vs 0/6——差距恰好落在"selector 腐烂"这个真实痛点上；M1/M2 两项双方都免疫（基线按属性定位），如实并列；M4 文案改写 5/6 是概率性边界，唯一失败的格子是断言绑定了录制时的原文案（页面文案变了断言就红——这是**测试的正确行为**），6 格样本不给出概率点估计。限定词主动说，不等追问。

### 卡 3：492 条测试的构成

一口气版：**`uv run pytest tests/record2gherkin -q` → 492 passed（2026-09-24 实测 94.45s）。构成：五模块 301（recorder 21 + distiller 68 + evaluation 77 + attributor 81 + cli 54）+ benchmark 191 = 492（--collect-only 逐模块实测）。**被问测试质量时主动讲自己的缺陷：session 级 playwright fixture 与 CLI 的 sync 实例冲突，特定子集乱序会误红 6 条——知道根因、官方全量入口绿、修法是一行 fixture scope。

### 卡 4：关于 Agent-E 和 81.6% 的说法边界

**三不说：**
1. 不说"分数超过 Agent-E"——它从未发表过 MiniWoB++ 数字，唯一公开数字是 WebVoyager 73.2%（GPT-4-Turbo、人工评判），和我方口径零交集
2. 不说"距 Agent-E 差 20 个百分点"——这个叙事建立在错误归属上，已废弃（round4 报告原文旁已加更正标注，权威更正固化在 baselines.md）
3. 不把 81.6% 当任何人的 MiniWoB 通用成绩引用；若面试官主动提，给出更正：81.6% 是 **HxAgent**（arXiv 2608.15491）的数字，且四重口径不可比（只挑 5 个任务族×25 实例 / GPT-4o 多模态 / 训练期注入经验 / 动作序列金标判分、方差 ±34.6）

**两说：**
1. 说"**机制组件对照无缺失**"：实克隆 Agent-E 仓库 HEAD（f218c3c）逐文件 diff，13 项机制组件（分层 planner、md/mmid DOM 蒸馏、mutation observer 变化观察、LTM、技能集等）我方已继承或改造后覆盖；论文传说的 Curious Reflector/独立 self-evaluator 在论文 v1 与仓库 HEAD 里都不存在
2. 说"**判分完整性领先**"：页面原生判分 + own-seed 过滤 + 五类作弊扫描，对比它的人工/字符串判分；另有多域编排（七类 helper 路由 vs 仅 browser）、上下文/token/超时治理、DOM 覆盖、工具超集（22+7 个工具）

一句话总结："我们不是在追一个更强的祖先，而是已经分化出更严的评测文化。"

## 5. 红线清单（简历和口头都绝不能说错的话）

1. **绝不引用 81.6% 当锚点或对比分数**——那不是 Agent-E 的数字（是 HxAgent 的、口径还不可比）；也绝不再说"距 Agent-E 差 20 个百分点"这句旧话（已废弃）。
2. **绝不说 "SOTA" / "刷榜" / "超过了 GPT-4"**——只说"越出同口径公开可比带（47-60%）上沿"；不同口径的数字（HxAgent 81.6%、97.4%、Synapse 99.2%）一律不直接比。
3. **绝不贬低或隐瞒上游**：不暗示执行内核是自己写的。被问"哪些是你写的"必须诚实分层——执行内核是开源的 Hercules（AGPL，要能讲清它的 planner→executor→assertion 流程和语义选择机制），录制器/蒸馏器/评测框架/归因器/编排 CLI/benchmark 改进包与全部实验设计是自己写的。
4. **绝不夸大自研比例**：不说"自研 AI 测试平台全栈"；简历标题必须带"基于开源执行内核二开"限定（本材料三个变体已带）。
5. **绝不隐瞒设置放宽**：240 秒（原版 10 秒）、单 seed 单次、Gherkin 中转、GLM 模型——四个披露项必须主动讲，等被挖出来就是失分。
6. **绝不让 1.00 vs 0.667 / 6/6 vs 0/6 脱离限定词出现**：必须带"6 流程×5 变异×2 方法、单 demo 单模型"；绝不说"覆盖率/通过率 100%"；M4 的 5/6 必须并列讲（它既是边界不是缺点，也不是卖点）。
7. **绝不说"只差一步/追平即可"或承诺追平任何锚点**——被问差距的标准答法：先更正归属（81.6% 不是 Agent-E 的，各家数字口径互不可比），再讲我方剩余 48 格的构成已逐格分析、在 Agent-E 的机制箱里找不到对应钥匙，下一步方向由数据指明。
8. **绝不把没做的事说成已做**：majority-of-3 多 seed、截图升级观察、480s 对照实验、多页录制支持、--polish/--llm 真机验收——这些全是"已设计/已规划"，不是"已做"。
9. **现场演示两条铁律**：不录多页站点（录制脚本随页面跳转销毁，会异常退出）；不开 --polish/--llm 现场真跑（要 60 秒以上、依赖 key、翻车点多）——只用离线四命令 + 固化录屏。
10. **密钥零出现**：任何材料、口头、GitHub 页面都不出现 key 内容；LLM-Key.txt 只讲机制（"gitignored 密钥文件、env 注入、日志强制脱敏"），不展示文件。
11. **测试数字不说满**：492 是"pytest 用例数"，不是"覆盖率 100%"；被问质量就主动讲 fixture 乱序误红 6 条的自知缺陷（反而加分）。
