# 实验报告 — exp001：「录制即用例」vs selector 基线的 UI 变异存活率对比

> 固化时间：2026-09-21。原始数据：`dev_runs/experiments/exp001/`（gitignore，本报告为结论快照）。
> 执行 LLM：deepseek-v4-pro（全角色单模型）。demo 应用与变异引擎：`record2gherkin/evaluation/`（seed 派生自格坐标，字节级可重复）。

## 1. 实验设计

- **方法 A（本工具）**：playwright 注入录制器 → JSON 事件流 → 确定性规则蒸馏（纯模板，零 LLM）→ Gherkin → Hercules 语义化自主执行
- **方法 B（基线）**：同一批流程的 selector 式 Playwright 脚本（仅按 id/data-testid/class 属性定位，模拟 codegen 产物的维护形态）
- **变异集**（对 demo 应用渲染参数施加，非事后改 DOM）：
  - M0 对照（无变异）
  - M1 表单字段顺序调换、M2 布局与 DOM 嵌套微调、M3 id/class/testid 按 seed 随机化（**主指标**）
  - M4 按钮文案改写（副指标，文献与阶段 1 分析均预测为概率性）
- **矩阵**：6 条录制流程 × 5 变异 × 2 方法 = 60 格；通过判定 = JUnit XML 无 failure
- **预算护栏**：Hercules 真实执行 30 + pilot 3 + 基础设施重试缓冲 ≤ 7，实际 33 次成功执行（pilot 前两轮 8 次失败在浏览器初始化，未产生 LLM 成本）

## 2. 结果

| 方法 | M0 对照 | M1 字段调换 | M2 布局 | M3 动态 id | M4 文案改写 | **主指标（M1/M2/M3 均值）** |
|---|---|---|---|---|---|---|
| **录制→蒸馏→语义执行（本工具）** | 6/6 | 6/6 | 6/6 | **6/6** | 5/6 | **1.00** |
| **selector 式基线** | 6/6 | 6/6 | 6/6 | **0/6** | 6/6 | **0.667** |

- **首轮通过率（FirstPass，M0）**：生成用例 6/6 = 1.00
- **成本**：30 次 Hercules 执行共 4,109,386 token（均值 136,980/次；简单流程 F1 实测 7.3 万，复杂表单流程 F3 约 42 万）。DeepSeek 前缀缓存会显著折扣实际费用；litellm 价格表无该型号，USD 成本字段不可得（cost_unavailable），以 token 计量。

## 3. 结论与边界（如实口径）

1. **主结论**：语义化执行的生成用例在标识符变异（M3，id/class/testid 全部随机化）下存活率 6/6，selector 基线 0/6——差距恰好落在真实世界"selector 腐烂"的痛点上；字段调换与布局变异两种方法都免疫（基线按属性定位也不受影响），如实并列。
2. **M4 文案改写是概率性边界**：本工具 5/6（唯一失败 F5：断言步骤绑定了录制时的原文案，页面文案改写后断言失败——这是**测试的正确行为**而非自愈缺陷；其中操作步骤全部语义映射成功，失败仅在 Then 断言）。基线 6/6（属性选择器天然不看文案）。宣传时必须并列此边界。
3. **唯一失败格的归因闭环**：F5/M4 失败运行经归因器（规则层 S10 签名 + 无 LLM 降级）产出报告，根因证据直指文案改写（`Missing: '去下单' (found '马上下单')`），替代假设含"用例过时"——诚实降级设计在真实失败上成立。
4. **已知局限**：单 demo 应用、6 条流程、单模型（deepseek-v4-pro）；M4 样本量 6 格不足以给出概率点估计；checkbox 双事件（click + enter "true"）在 F3 中未阻碍执行。
