## 5. 面试问答弹药清单（问 → 答要点）

**A. 定位与对比**

1. **"和 Playwright codegen / Selenium 区别？"** → codegen 产死 selector，改版全挂（exp001 实证：M3 标识符随机化下基线 0/6）；本工具录制成自然语言意图 + grounding 断言，agent 每次现场理解 DOM；且失败有归因闭环而不是红一片靠人翻。
2. **"和 Agent-E 什么关系？"** → Hercules 是 Agent-E 直系前身的同源架构（planner→executor LangGraph）；我在其上做了录制蒸馏前端 + 评测 + 归因 + 四轮基准改进。61.6% vs Agent-E 81.6%：差 20pp，主要在视觉/几何类任务（文本-DOM 观察天然盲区）与单 seed 方差，差距构成有逐格分析支撑。
3. **"和 browser-use / Playwright MCP 这类通用 agent 区别？"** → 它们是通用自动化工具，本工具是**测试生产管线**：解决的是"用例从哪来（录制蒸馏）、坏了算谁的（归因定类：产品 bug / 用例过时 / 环境 / agent 限制）"这两个测试工程问题，agent 只是执行内核。
4. **"哪些是你写的？"** → 诚实分层：执行内核开源（能讲清 planner→executor→assertion 与 md 语义选择）；录制器/蒸馏器/评测框架/归因器/编排 CLI 是我写的；benchmark 四轮的 harness、改进包（引擎 flag 化补丁）与全部实验设计是我的。

**B. 数字口径**

5. **"61.6% 什么口径？"** → 一句话版：MiniWoB++ browsergym registry 全量 125 任务、零样本文本-DOM 观察（md 属性蒸馏，非视觉）、GLM 5.3 全角色、episode 240s（原版 10s，放宽已披露）、单 seed 单次、页面原生奖励判分（无 LLM 裁判）、官方=clean 零无效格。公开可比带（零样本文本-DOM GPT-4 级）47-60%，我们越出上沿。
6. **"为什么不用 GPT-4 跑个更高分？"** → 分数目标是"口径可比"不是"刷榜"；单模型 coding-plan 额度内完成 12.2M token/轮，四轮每格归因。
7. **"实验样本是不是太小？"** → 主动给限定词：exp001 是 6 流程 × 5 变异 × 2 方法的受控实验，单 demo 单模型，结论是机制性差异（M3 6/6 vs 0/6）而非规模估计；M4 5/6 是 6 格样本不给概率点估计——这些限定词写在报告里，不等追问。
8. **"M1/M2 基线也全过，你的优势在哪？"** → 恰恰说明基线不是稻草人：属性定位天然免疫字段调换/布局微调，差距全部集中在真实痛点"selector 腐烂"（M3），这个口径反而加分。

**C. 设计决策**

9. **"蒸馏为什么骨架零 LLM？"** → 正确性不能赌模型：规则模板保证语法与字面值必然真实（事实回查不过即回退纯模板），LLM 只做润色，坏了不影响骨架——对模型能力零依赖的设计。
10. **"断言是 LLM 编的吧？"** → 断言来自录制时真实 DOM 快照（assert_texts grounding），非模型想象；文案改写变异下断言红是**测试的正确行为**（M4 5/6 的唯一失败格，操作步骤仍全语义映射成功）。
11. **"归因器怎么保证不瞎编？"** → 规则签名优先（13 签名命中即定类，LLM 不参与）；LLM 摘要强制引用证据（日志行/截图/tool 原文），程序回查引用存在性，查无此证强制降级"无法定位"——宁可疑而不定。
12. **"为什么基于 Hercules 不自己写执行内核？"** → 两周约束内自研 agent 内核不可能达到可评测质量；选它的标准是：LangGraph 编排可讲清、md 语义选择机制与我的录制器同源对齐、AGPL 对秋招展示无碍。二开边界画得清（不改 testzeus_hercules/，引擎改动全部 flag 化默认 off + off golden 逐字节锁定）。

**D. 工程可靠性**

13. **"踩过最深的坑？"** → 首选 max_tokens no-op：flag 注入链验证在位、端点实测 768 配置产出 19,349 token——"声明在位≠生效"；我的处理是实测证伪后在自己报告里修正为 no-op 并摘除 flag（round3 §3 完整性披露）。次选 NLTK 语料挂死（r1 3 格无头挂死，诊断到语料下载阻塞，r2 预装）。
14. **"怎么防 agent 作弊刷分？"** → 页面原生奖励为唯一权威（无 LLM 裁判）、HUD/重开层对 agent 观察封死、五类作弊扫描（重导航/file://、沙箱调用、奖励行数自洽等）、每轮 pre/post 双审查；r2 一次成功路径绕过扫描（persist_findings），按预登记契约 10 格无效化压分——宁可掉分不洗分。
15. **"测试怎么保证的？"** → 492 条（实测复验）；并且能讲自己的缺陷：recorder session 级 playwright fixture 与 CLI 的 sync 实例冲突、特定子集顺序会误红 6 条——知道问题在哪、为什么官方全量入口是绿的、修法是一行 fixture scope。
16. **"多页站点能用吗？"** → 如实：v1 明确 scope out，检测到跨文档导航干净退出不落脏数据；v2 方案（导航重注入 + 多段合并）已写入边界。

**E. 收束**

17. **"下一步做什么？"** → r5 方向已由数据指明：距 Agent-E 20pp 的差距构成分析、多 seed 口径决策、不可寻址元素覆盖审计——用数据指路而不是拍脑袋。
18. **"为什么适合我们组（前端缺 AI 测试）？"** → 这个项目就是给前端组的答案：用例生产成本≈0（录制即得）、selector 腐烂维护成本≈0（语义执行）、失败能定责（归因）；且我能讲清楚它哪 5/6、哪 0/6——不吹全覆盖。
